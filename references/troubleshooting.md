# 故障排查

## 抓包相关

**一直检测不到凭证（auth_fresh 始终 false）**
1. 确认已安装 mitmproxy CA 证书：抓包启动后浏览器打开 <http://mitm.it>，下载 Windows 证书，安装到"受信任的根证书颁发机构"。装完重启微信电脑版。
2. 确认系统代理已开启且指向 `127.0.0.1:8898`（`capture status` 里 `proxy_on`/`proxy_points_to_us` 均为 true）。
3. 确认是在**微信电脑版**里点开主页链接，不是普通浏览器（普通浏览器不携带微信登录态）。
4. 看 `data/mitm.log` 是否有 `[AUTH CAPTURED]` 日志。

**抓包进程启动后立即退出**
- 看 `data/mitm.log`。本工具用 `mitmproxy.tools.main:mitmdump` 入口兼容 mitmproxy v12；若自行升级/降级了 mitmproxy 导致入口变化，请按 `requirements.txt` 固定版本重装。

**`__biz` 识别成 `${window.biz}`**
- 已修复：种子解析会校验 `__biz` 必须匹配 `^[A-Za-z0-9=_-]{8,}$`，跳过 JS 占位符。若仍失败，换一篇该号文章作为种子链接。

## 网络 / 代理相关

**电脑无法上网（最常见：代理开着但抓包进程没运行）**
- 立即双击 `reset_network.bat`，或执行 `python scripts/cli.py reset`，或网页点「一键恢复网络」。
- 原理：抓包时系统代理被临时指向 `127.0.0.1:8898`；若抓包进程意外退出而代理没关，流量会打到无人监听的端口导致断网。工具内置守护线程每秒检测并自动回滚，但手动急救最快。
- 工具只回滚自己设置的代理，不会动用户原有的代理配置。

**采集完忘记关代理**
- 执行 `python scripts/cli.py capture stop` 或网页点「停止并恢复代理」。

## 采集相关

**返回 ret 异常 / 凭证过期**
- 凭证约 30 分钟有效。重新执行 `capture start` → 微信里点主页链接 → `capture status` 确认 `auth_fresh: true` 后再采集。CLI 可用 `--force` 强行继续但不推荐。

**采集篇数偏少 / 提示达到页数上限**
- 把 `--pages` 设为 0（尽量拉全至 3000 页）；`getmsg` 翻页有平台上限，部分老号无法保证全量，可反复采集自动去重补全。

**翻页中途想停**
- 网页模式点「暂停/停止」；CLI 当前版本为一次性跑完（可在采集后增量补采，已入库数据不会重复）。

## 正文抓取相关

**正文抓取大量失败**
- 正文抓取依赖抓包得到的 Cookie/UA。先完成一次抓包再抓正文；微信偶发返回验证页，工具自带重试。纯图片/视频文章可能无文本，属正常。

**归档导出为空**
- 先执行 `content` 抓取正文，确认 `content_status=ok` 后再 `archive`。

## 其他

**端口被占用**：Web 默认 8899、抓包代理默认 8898，均在 `core/config.py` 里可改。
**服务未启动**：网页模式需先双击 `start.bat`；CLI 模式无需 Web 服务，直接调用 core 模块。
